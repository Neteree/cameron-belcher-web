# Cameron Belcher web

Cameron's own business site: websites (and games) for local Auckland businesses. It is a starter site like any client's, made from `starter/clients/cameron-belcher.json` in `Neteree/new-empty-repo` (see its CLAUDE.md for the decisions, agents and the client request plan). Don't hand-build pages or components here: change the starter or a module there, then bring it in with update-site, so every site gets the improvement.

- **Update from the starter:** with `new-empty-repo` cloned next to this repo, `node ../new-empty-repo/starter/scripts/update-site.js .`, then `npm install && npm run check`. It replaces code only, never this site's content. `--add <module>` / `--remove <module>` adds or takes out an add-on.
- **Content (edit these, or use the change scripts):** `src/data/site.json` (name, headline, enquiry form, studio look, `formKey`, `intakeUrl`, `url`), `src/modules/*/*.json` (highlights, work, prices, steps, faq, and the Get started form's wording and list in `start/start.json`), photos in `src/assets/photos/`, icons and the link-preview image in `public/` (`npm run share-images` redraws them; the current ones are hand-made).
- **Pricing model:** no monthly fees. A $150 base site, one-off add-ons, then pay per request for changes. Prices are in `src/modules/prices/prices.json`. Discounted or free deals are word of mouth only, never on the site.
- **Portfolio:** `src/modules/work/work.json`. Every item is a demo and keeps `"demo": true` (the "Demo" tag) until it's replaced with real client work (with permission). Lantern Market is the game demo.
- **Get started:** `start.html` (the `start` module) is the one form for everything: a new website (their business; "Build your site", a list of what's included and the add-ons with prices from `src/modules/prices/prices.json`, plus "Something else?" for anything custom, quoted; a look; contact details), a change to their website (the change request form, linked from client emails as `start.html?path=change&site=<their site URL>`, the same list as a new website: each section their site has opens its changes, anything else can be added), or a question. The hero button and the contact section link to it. With `intakeUrl` set (the live intake Worker) everything goes into the request queue and Web3Forms only sends Cameron a heads-up; `formKey` is the public Web3Forms key. Nothing is built, changed or shown to a client until Cameron has checked it. The old `onboarding.html` and `request.html` links redirect here. `npm run check` fails if the change form can send a change type `scripts/changes.js` doesn't handle.
- **Hosting:** Cloudflare Pages (live at https://cameron-belcher-web.pages.dev, deploys every push to `main`), build command `npm run build`, output folder `dist`. Node version in `.node-version`. Change `url` in `site.json` if a custom domain is added.
- **Checks:** `npm run check` builds, then checks HTML, spelling (NZ/UK English; add real names to `cspell-words.txt`), phone and desktop layout, images, links, forms, accessibility (including colour contrast) and the modules' own checks. Run it before every push; GitHub Actions also runs it on every pull request.
- **Parked (Cameron to set up later):** custom domain. See the Parked list in `new-empty-repo`'s CLAUDE.md.
