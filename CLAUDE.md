# Cameron Belcher web

Cameron's own business site: websites (and games) for local Auckland businesses. It is a starter site like any client's, made from `starter/clients/cameron-belcher.json` in `Neteree/new-empty-repo` (see its CLAUDE.md for the decisions, agents and the client request plan). Don't hand-build pages or components here: change the starter or a module there, then bring it in with update-site, so every site gets the improvement.

- **Update from the starter:** with `new-empty-repo` cloned next to this repo, `node ../new-empty-repo/starter/scripts/update-site.js .`, then `npm install && npm run check`. It replaces code only, never this site's content.
- **Content (edit these, or use the change scripts):** `src/data/site.json` (name, headline, enquiry form, studio look, `formKey`, `intakeUrl`, `url`), `src/modules/*/*.json` (highlights, work, prices, steps, faq, and the wording of the onboarding and request pages), photos in `src/assets/photos/`, icons and the link-preview image in `public/` (`npm run share-images` redraws them; the current ones are hand-made).
- **Pricing model:** no monthly fees. A $150 base site, one-off add-ons, then pay per request for changes. Prices are in `src/modules/prices/prices.json`. Discounted or free deals are word of mouth only, never on the site.
- **Portfolio:** `src/modules/work/work.json`. Every item is a demo and keeps `"demo": true` (the "Demo" tag) until it's replaced with real client work (with permission). Lantern Market is the game demo.
- **Contact form:** the starter's enquiry form, with the "Your business" field. `formKey` is the public Web3Forms key; with `intakeUrl` set (the live intake Worker, https://cameron-belcher-intake.neteree.workers.dev) answers go into the request queue and Web3Forms only sends Cameron a heads-up.
- **Onboarding:** `onboarding.html` (the `onboarding` module; private: not linked, `noindex`) collects a new client's details, hours, look, photos and add-ons, sent with a `---CLIENT-JSON---` block that the starter's `scripts/onboard.js` turns into their site. Add-ons come from the link (`?modules=food,prices`, plus `&preorder=1` or `&quote=1`). The looks and add-on list are read from the starter (`src/lib/catalogue.ts`, `src/data/modules.json`), never kept by hand.
- **Change requests:** `request.html` (the `requests` module; private, `noindex`, linked from client emails as `request.html?site=<client site URL>`, which loads that site's `photos.json`). It sends a `---CHANGES-JSON---` block that `ops/intake.js` reads; `npm run check` fails if it can send a change type `scripts/changes.js` doesn't handle.
- **Hosting:** Cloudflare Pages (live at https://cameron-belcher-web.pages.dev, deploys every push to `main`), build command `npm run build`, output folder `dist`. Node version in `.node-version`. Change `url` in `site.json` if a custom domain is added.
- **Checks:** `npm run check` builds, then checks HTML, spelling (NZ/UK English; add real names to `cspell-words.txt`), phone and desktop layout, images, links, forms, accessibility (including colour contrast) and the modules' own checks. Run it before every push; GitHub Actions also runs it on every pull request.
- **Parked (Cameron to set up later):** custom domain. See the Parked list in `new-empty-repo`'s CLAUDE.md.
